# Dashboard UX audit, 16 Nov 2026

Issue #226. Asked for by the stakeholder on 16 Nov 2026: check layout, overflow, phone screens, transitions, and the amount of
text on phones. This file holds the measurements. The redesign that answers them is in `mobile_first_v4.md`.

## How it was measured

- **Build:** `apps/web` at `main` (`e6deca3`), production build (`npm run build`), no code changes.
- **Data:** a dev-only mock in `audit_2026-11-16/tools/mock_data.py`. It answers the dashboard's database calls inside the test browser.
  Every number is invented. No production data, account or key was used. Nothing in `apps/web` imports it.
- **Scenarios:** *running* (a paper run, four Trend momentum positions, the experiment label, one halt: 3 losses in a row)
  and *empty* (a new run with nothing traded).
- **Browser:** Chromium through Playwright, one at a time. Phone widths use touch and phone emulation.
- **Routes (13):** Home, Trades, Tape, Trade detail, Report, Engine, Go / no-go, Run & settings, Strategy (Configure),
  My lists, Fine-tune, New run, Sign in.
- **Viewports (6):** 375x812, 390x844, 430x932, 768x1024, 1280x800, 1440x900. The app has one theme (dark), so there is no
  light pass.
- **Checks:** page wider than the screen, elements past the right edge, tables wider than their box, tap targets under
  44 px and under 24 px, text under 12 px, words and numbers above the fold, layout shift on load, keyboard focus rings
  (45 Tab presses), axe-core 4.10 (WCAG 2 A/AA, 2.1 AA, 2.2 AA), and running animations with reduced motion on.
- **Result:** 90 page loads, 0 JavaScript errors.

To run it again: build the app with `VITE_SUPABASE_URL=http://localhost:54321` (a placeholder nothing listens on), then
`python audit_2026-11-16/tools/audit.py --dist apps/web/dist --axe <axe.min.js> --out /tmp/kb-audit` and
`python audit_2026-11-16/tools/report.py /tmp/kb-audit docs/design/audit_2026-11-16`.

### Limits of these numbers

- **Layout shift on phones reads 0 on every page.** Chromium reported no shift entries in phone emulation, while the same
  pages shift on desktop. Treat phone layout shift as not measured, not as good.
- **The mock answers instantly.** On a real connection the page waits longer for data, so shifts are more visible.
- **"Words above the fold"** counts every visible word in the first screen, including the header and the tab bar.
- **Contrast** is checked by axe-core only where it can read both colours. It reported no failures; it does not check
  text over gradients or charts.
- **Not tested:** real phones, Safari, screen readers, slow networks.

Likely cause of #1, from reading `app.css` (not yet proven by a fix): the phone carousels `.kb-presets` and `.kb-tgrid` use
`display: flex; overflow-x: auto` with negative side margins inside a column whose children have no `min-width: 0`, so the
carousel's full content width (1,093 and 1,930 px) widens the page.

### What passed

- **No page is wider than the screen** on Home, Trades (390 and up), Tape, Trade detail, Report, Engine, Go / no-go,
  Settings, Fine-tune and Sign in, at any width.
- **Focus rings:** every Tab stop shows a ring, on all 13 pages. The 4 stops flagged on My lists and 2 on Fine-tune are text
  inputs whose wrapper shows the ring (`.kb-search:focus-within`), so they pass.
- **Contrast:** axe-core found no text contrast failures.
- **Reduced motion:** with the system setting on, no animation runs.
- **No clipped text** was found by the overflow check, apart from #5.
- **Paper, halt and experiment labels** are present on every page that should carry them.

## Motion review (from the code)

| What | Now | Problem |
|---|---|---|
| Page change | Every direct child of `main` rises 12 px and fades in, 550 ms, staggered up to 300 ms (`kb-rise`) | The last card settles 850 ms after a tap. Feels slow on a page the person opens ten times a day. There is no exit, so pages cut out and rise in. |
| Loading | Shimmer skeletons shaped per page (`Skeleton`), `role="status"` | Good. The shimmer animates `background-position`, which repaints every frame; fine on a few bars, costly on a long list. |
| Live dot | `kb-pulse` animates `box-shadow` forever | Repaints every frame while the page is open. |
| Numbers | No animation. The pot, P&L and meters swap text on each 5 s poll | A change is easy to miss, and there is no cue that the page is live. |
| Chart range | `PotChart` is re-created on each range change (`key={range}`), so the 1.1 s grow-in replays | The `transition: d` rule written for a smooth morph never runs. |
| Meters and bars | `transition: width .6s` and `kb-growX` on load | `width` triggers layout; `transform: scaleX` would not. |
| Expanding rows | Tape transcript and Fine-tune rows appear with `kb-rise` (300 ms) | Height does not animate, so content below jumps. |
| Halt strip | `kb-rise` 350 ms on insert | It pushes the page down (finding #9). |
| Confirm "Flatten and stop" | Inline panel swaps in (`swap`, 350 ms) | Fine. On phones a bottom sheet would be clearer. |
| Reduced motion | One global rule turns off every animation and transition; `reducedMotion()` helper in JS | Works (measured: 0 running). Skeletons fall back to a flat tone. |
